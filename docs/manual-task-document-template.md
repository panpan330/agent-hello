# 每节手动操作清单文档模板

这个文档用于固定后续学习的新协作方式。

从下一节开始，如果一节课涉及外部服务、长时间测试、真实 smoke、Docker、MySQL、Redis、Qdrant、Milvus、真实模型调用或 GitHub 上传前验证，除了主学习笔记之外，还要额外生成一个手动操作清单文档。

推荐命名方式：

```text
notes/<本节笔记文件名去掉 .md>-manual-tasks.md
```

例如：

```text
notes/stage7-075-java-service-traditional-mybatis-refactor.md
notes/stage7-075-java-service-traditional-mybatis-refactor-manual-tasks.md
```

## 目的

减少助手自动执行长时间命令、真实外部服务验证和大段日志读取，降低等待时间和 token 消耗。

当学习者说“省 token 模式”或“省token模式”时，默认启用本协作方式。

新的默认分工是：

```text
助手负责：教学设计、代码修改、主笔记、手动操作清单、根据你贴的结果排查问题。
学习者负责：运行手动操作清单里的外部服务检查、长时间测试、真实 smoke、关键结果回传。
```

## 每节手动操作清单必须包含什么

每个 `*-manual-tasks.md` 至少包含：

```text
1. 本节哪些操作建议你手动做。
2. 为什么这些操作适合你手动做。
3. 每条命令在哪个终端运行：Windows PowerShell、IDEA、VMware Ubuntu、MySQL Shell 等。
4. 运行前需要确认什么。
5. 具体命令。
6. 预期成功结果。
7. 如果失败，只需要贴给助手哪些关键输出。
8. 哪些长日志不要整段贴，除非助手要求。
9. 哪些清理动作需要做。
10. 完成后把结果按什么格式发给助手。
```

## 学习者回传格式

建议你以后按这个格式贴结果：

```text
手动操作结果：

1. 命令：mvn test
   结果：BUILD SUCCESS

2. 命令：Test-NetConnection 192.168.88.10 -Port 6379
   结果：TcpTestSucceeded=True

3. 命令：curl.exe http://localhost:8002/health
   结果：{"service":"java-business-service","status":"ok"}

异常：
无
```

如果失败，贴：

```text
失败命令：
失败现象：
关键报错前后 20 行：
你运行命令的位置：
你认为可能的原因：
```

## 助手默认不再自动做的事情

除非学习者明确要求，后续每节默认不再由助手自动完成这些耗时操作：

```text
真实 Docker 服务启动和停止。
真实 MySQL / Redis / Qdrant / Milvus smoke。
长时间 Maven 全量测试。
长时间 pytest 全量测试。
真实模型 API smoke。
大段日志读取和全文粘贴分析。
GitHub 上传前的重复大范围验证。
```

助手仍可以做这些轻量检查：

```text
查看文件和代码结构。
小范围语法或静态检查。
必要的短测试。
git diff --check。
敏感信息扫描。
根据你贴回来的结果定位问题。
```

如果某一节为了保证代码正确性必须由助手亲自跑某个命令，助手要先说明原因和预计耗时。

## 注意

这份手动操作清单不替代主学习笔记。

主学习笔记仍然要保证高质量，尤其是：

```text
基础知识铺垫
本节主题系统讲解
关键代码讲解
常见误区
练习和答案
自测和答案
```

手动操作清单只负责把“你可以自己运行的验证步骤”单独拆出来。
