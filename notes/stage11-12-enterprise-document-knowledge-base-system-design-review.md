# M11 第 12 节：企业文档知识库的完整方案设计与复盘

## 本节定位

本节不新增一个孤立技术名词，而是把 M11 的 PDF、OCR、清洗、分块、元数据、入库、版本、权限、引用和评估组织成一套面对真实需求可使用的设计方法。

目标不是画一张堆满组件的架构图，而是能够解释：为什么需要这些组件、它们各自保护什么、出了问题怎样定位、约束变化后怎样取舍。

## 本节学习目标

1. 从用户、资料、风险、更新和合规拆解文档 RAG 需求。
2. 画出离线加工、在线问答和知识治理三条完整链。
3. 明确每个组件的责任边界与输入输出。
4. 能针对真实约束选择解析、索引、权限、发布和评估方案。
5. 能用清晰工程语言介绍一套企业文档知识库。

## 一句话先讲透

**企业文档知识库不是 OCR、向量库和大模型的拼装题，而是围绕可信资料、正确访问、可靠证据和持续治理构建的数据产品。**

## 基础知识铺垫

### 1. 系统设计从问题开始

面对“做 PDF RAG”需求，先不要问用哪个框架。应先澄清：

```text
谁使用：客户、客服、员工、审核人员？
资料是什么：原生 PDF、扫描件、表格、网页、附件？
资料多久更新：实时、每月、每年，是否查历史？
风险是什么：答错、越权、错金额、错版本哪个最严重？
权限如何划分：租户、部门、角色、密级、地区？
用户需要什么证据：文件名、页码、原图、完整条款？
证据不足时：拒答、转人工还是补充资料？
```

这些答案决定技术取舍。脱离业务约束谈“最佳向量库”没有意义。

### 2. 功能需求与非功能需求

功能需求是上传、解析、检索、回答、引用；非功能需求是准确性、权限、延迟、成本、审计、可删除、可回滚和可运营。

在文档 RAG 中，很多最关键设计由非功能需求决定：要不要 OCR、是否独立租户索引、能否保留历史版本、引用要到什么粒度、资料删除多久生效。

## 本节主题系统讲解

### 1. 三条链路的总架构

```text
离线知识加工链
原始文件
-> 文件登记、来源、版本与权限
-> 文本提取 / OCR / 版面恢复
-> 清洗、结构恢复与质量标记
-> 语义分块与元数据
-> embedding、全文/向量索引
-> 验证与候选发布

在线问答链
用户身份 + 问题
-> 授权、租户、状态、有效期过滤
-> 关键词/向量混合召回
-> rerank、去重、父子上下文补全
-> 选择证据
-> 模型基于证据回答
-> 引用、页码、版本和边界说明

知识治理链
版本、生效、失效、删除、重建、权限撤销、评测、bad case、审计、监控
```

三条链通过稳定文档 ID、版本、权限、处理版本与引用定位连接。它们不是三套独立系统，而是同一份知识的不同生命周期。

### 2. 组件责任表

| 组件 | 应负责 | 不应负责 |
| --- | --- | --- |
| 原始文件存储 | 保存原件、来源、受控访问 | 语义问答 |
| 文档目录 | 版本、状态、权限、生命周期 | 相似度搜索 |
| 解析/OCR/版面 | 读取文字与结构 | 最终业务裁决 |
| 清洗分块流水线 | 产生可追溯证据块 | 补写原文事实 |
| 向量/全文索引 | 召回候选与过滤承载 | 原始权威来源 |
| rerank | 候选排序 | 修复源数据丢失 |
| LLM | 解释、归纳、拒答 | 权限、版本、法律效力 |
| 授权系统 | 身份、角色与范围 | 让模型自行守密 |
| 评估运营 | 发现回归与趋势 | 替代业务资料审核 |

明确“不应负责什么”尤其重要，它能防止模型被当成万能规则引擎。

### 3. 十个关键设计决策

1. 资料准入：哪些格式自动处理，哪些需要审核？
2. 解析路径：原生文本、扫描件、表格、图表分别怎么走？
3. 证据边界：FAQ、条款、步骤、表格行如何分块？
4. 元数据：来源、版本、页码、状态、有效期、权限放在哪里？
5. 索引：关键词、向量、混合检索与 rerank 如何组合？
6. 权限：租户、角色、部门、密级如何成为检索前硬过滤？
7. 发布：新版本怎样验证、切换与回滚？
8. 回答：证据不足、冲突、无权限时怎样表达？
9. 引用：用户怎样核验正确版本、页码、表格或脚注？
10. 质量：如何评测、监控、收集 bad case 与持续改进？

能够解释这些决定，比单纯列出十个框架更接近真实工程能力。

### 4. 用需求推导方案：售后政策助手

需求：客服查询售后政策 PDF；普通客服只看公开客服政策，主管可看内部升级流程；政策每月更新；回答必须显示版本和页码。

推导：

```text
资料：先诊断文本层、扫描页、表格和脚注。
分块：按政策章节、条款、条件、例外与 FAQ 组织。
元数据：文档/版本/页码/章节/生效期/角色权限/状态。
检索：先按角色、状态、有效期硬过滤，再混合召回与重排。
发布：新版本后台完整处理与验证，成功后替代默认版本。
回答：仅使用已授权证据，返回版本、页码与章节；证据不足转人工。
治理：旧版本退出默认检索，历史查询需目标时间和额外授权；失败进入评测集。
```

这就是从业务风险推导技术，而不是先决定“我要用某个库”。

### 5. 常见取舍

| 选择 | 好处 | 代价 | 何时考虑 |
| --- | --- | --- | --- |
| 仅文本提取 | 快、便宜 | 扫描件和复杂布局差 | 文档质量高、风险低 |
| OCR/视觉处理 | 覆盖广 | 成本高、仍有误识 | 扫描资料价值高 |
| 单索引多租户过滤 | 管理简单 | 过滤遗漏风险高 | 权限模型成熟且测试充分 |
| 分租户索引 | 隔离直观 | 管理成本高 | 高敏感或强隔离场景 |
| 增量更新 | 快、成本低 | 差异与一致性复杂 | 文档稳定、指纹成熟 |
| 新版本全量构建切换 | 易验证和回滚 | 资源消耗大 | pipeline 大改、高风险发布 |
| 小块检索+父块回答 | 精确且保上下文 | 数据模型复杂 | 规则和例外较多 |

成熟表达是：“因约束 A 与风险 B，选 X，并通过 Y 控制代价 C。”

### 6. 最小上线验收清单

```text
文件：格式、加密、扫描页、超大文件和失败有明确状态。
解析：标题、页码、脚注、表格、乱码与低质量有门槛。
分块：条件、结论和例外可在同一证据范围获得。
元数据：来源、版本、状态、权限、有效期完整。
入库：幂等、失败可恢复、发布前验证。
更新：旧版本、禁用和删除内容退出默认检索。
权限：多租户/角色负向用例无旁路。
回答：关键结论有正确、可访问的引用；证据不足能拒答。
评估：普通、表格、版本、权限、拒答边界均覆盖。
运营：处理记录、失败原因、指标和 bad case 可追踪。
```

### 7. 运营责任与持续演进

架构图不等于系统可运行。还要明确：谁上传并审批资料、谁维护权限分类、解析失败谁处理、坏案例谁归类、何时重建索引、如何回滚、哪些指标告警。

务实建设顺序是：先选择资料范围清晰、可人工核验、权限简单的最小闭环；再补版本、增量更新和复杂权限；最后扩展多租户、复杂表格、自动审核和大规模运营。每一步都保留前一阶段的安全与质量底线。

### 8. 面试或工作表达示例

```text
我会把企业文档 RAG 拆成离线加工、在线问答和知识治理三条链。
离线侧先区分原生文本、扫描件和复杂版面，保留页码、章节、版本、权限等元数据，再按条款语义分块并建立检索索引。
在线侧先做租户、角色、状态和有效期过滤，再进行混合检索、重排和上下文补全；模型只基于已授权证据回答，并返回可定位的版本和页码引用。
对于更新、删除和 pipeline 升级，我会使用稳定 ID、内容指纹、候选版本验证和受控切换避免旧向量残留；质量则通过解析、检索、引用、权限和 bad case 回归共同评估。
```

这段表达展示的是设计逻辑与边界，而不是工具名堆砌。

## 常见误区

### 误区 1：架构图有 OCR、向量库和 LLM 就完整

不对。缺少版本、权限、引用、发布、删除和评估，系统无法长期可信运行。

### 误区 2：先定技术栈再找场景

不对。应先明确资料、用户、风险、更新和合规约束，再选择技术。

### 误区 3：项目上线后知识库就完成

不对。资料、权限、版本和问题不断变化，治理与运营才是长期能力。

## 本节练习

### 练习 1：请用三条链概括企业文档 RAG。

答案：离线加工链把原始资料加工为可检索证据；在线问答链在有权限、有效的证据中回答；治理链负责版本、更新、删除、评测、审计和持续改进。

### 练习 2：为什么权限必须在检索前过滤？

答案：无权内容一旦进入模型上下文就形成泄露面。模型拒答不能替代系统访问控制。

### 练习 3：举两个方案取舍例子。

答案：例如全量 OCR 提高扫描覆盖但增加成本与误识；分租户索引隔离强但管理成本高；增量更新快但一致性复杂。任意两个即可。

## 自测题

### 自测 1：企业文档知识库的四个核心目标？

答案：可信资料、正确访问、可靠证据、持续治理。

### 自测 2：模型只基于证据回答为何仍不足以保证安全？

答案：还需保证证据解析正确、版本有效、权限已过滤；模型不能替代数据生命周期与访问控制。

### 自测 3：M11 真正带走的能力是什么？

答案：能够从文档接入、解析、复杂内容、分块、元数据、入库、更新、权限、引用、评估和治理的全链路设计企业知识库，而不只会调 RAG 参数。

## M11 阶段总结

```text
原始文件是事实来源。
解析和清洗恢复内容与结构。
分块与元数据构造可检索证据。
检索和重排寻找证据。
权限、版本和状态决定哪些证据可被使用。
模型基于证据解释，而不创造事实。
引用、评估、更新和删除让系统可验证、可维护、可长期运行。
```

M11 的重点不是“PDF 入向量库”，而是建立企业文档知识工程的完整思维方式。
