# M11 第 3 节：文档清洗与结构化文本标准化

## 本节定位

上一节让系统“读到” PDF 内容。本节解决更隐蔽的问题：读到的字符、OCR 结果和页面区域，为什么仍不能直接交给分块和向量化？

文档清洗的目标不是把文字变漂亮，而是建立一个可追溯的中间层：它既去除呈现噪声，又保住标题、条件、脚注、版本、页码、表格关系等真正决定业务含义的信息。

## 本节学习目标

1. 区分原始解析结果、规范化文本、结构块和最终知识块。
2. 理解清洗、标准化、纠错、摘要与改写的边界。
3. 说明换行、页眉页脚、脚注、目录、重复与 OCR 错误该怎样处理。
4. 建立“保留原始证据、处理可回溯、异常可标记”的清洗原则。
5. 判断清洗质量是否足以进入下一步分块。

## 一句话先讲透

**清洗不是删除越多越好，而是在不改变原文事实和关系的前提下，移除可确认的呈现噪声，让每段内容仍然知道自己来自哪里、适用于什么。**

## 基础知识铺垫

### 1. 为什么解析文本仍会失真

解析器输出的是它从页面中读到的字符和区域，不是作者写作时的逻辑结构。常见现象：

```text
每页重复公司名、密级和页码。
视觉换行把一个段落拆成很多行。
标题与正文脱离。
目录和正文重复同一批标题。
OCR 在中文字符间插入空格，或误识别数字。
脚注、小字例外和版本号混入页脚或被误删。
```

这些内容若直接切块，检索会被页眉污染，模型会缺少例外，引用也无法定位版本和页码。

### 2. 五种动作的边界

| 动作 | 含义 | 典型例子 | 风险 |
| --- | --- | --- | --- |
| 保留 | 原样保存来源内容 | 原始页面、原始文字层 | 最低 |
| 清洗 | 移除已确认无意义噪声 | 重复装饰页眉 | 中低 |
| 标准化 | 统一表达形式 | 换行符、明显无意义空格 | 中低 |
| 纠错 | 修改识别或原文错误 | 修正 OCR 日期 | 高 |
| 改写/摘要 | 重组、解释、压缩原文 | 生成政策摘要 | 高，不能替代原文 |

把连续空格改成一个空格通常可以自动做；把“7 日”解释为“签收后 7 个自然日”已经改变或补充了语义，不能当作普通清洗。

### 3. 什么是规范化中间表示

不要使用：

```text
PDF -> 一大段字符串 -> 分块 -> 向量库
```

更稳的过程是：

```text
原始文件
-> 原始解析结果
-> 规范化的页面/结构块
-> 语义知识块
-> 索引
```

规范化结构块在概念上至少保留：页码、块类型、原始文字、清洗后文字、章节、顺序/坐标、处理版本和质量标记。它是检查、回滚和重新处理的依据。

## 本节主题系统讲解

### 1. 清洗的四项原则

```text
先保存原始信息，再产生派生结果。
先做低风险规范化，再做高风险判断。
能用确定规则解决的，不让模型猜。
无法确认的内容标记、复核或保留，不静默删除。
```

制度、合同、政策里一个“除外”“不得”“以最新版本为准”就可能改变结论。因此清洗首先追求保真，其次才是整洁。

### 2. 安全的清洗流水线

```text
原始解析块
-> 字符、编码与空白规范化
-> 页眉页脚和重复元素识别
-> 标题、段落、列表、表格、脚注结构恢复
-> 视觉换行与断词处理
-> 版本、页码、脚注与正文关系保留
-> 去重与质量检查
-> 输出规范化结构块
```

拆成阶段的好处是能回答“哪一步让一条规则丢失”。不要把所有处理塞进一个无法解释的大函数或一次模型改写。

### 3. 空白、换行与断词

视觉换行和逻辑换行不同：

| 场景 | 更合理的处理 |
| --- | --- |
| 同段落视觉换行 | 合并成连续正文 |
| 段落空行 | 保留段落边界 |
| 标题后换行 | 保留标题与正文关系 |
| 列表项 | 保留编号、层级与引导句 |
| 表格内换行 | 按单元格处理，不粗暴拼接 |
| 英文行末断词 | 有证据时谨慎合并 |

中文通常不能照搬英文断词规则。更不能删除所有短横线，因为订单号、条款编号、型号中的短横线有业务含义。

### 4. 页眉、页脚、页码和版本

跨页重复不等于无价值。应分类处理：

```text
纯页码：从正文移出，但保留为页码元数据。
重复公司名：可从正文移出或降权。
文档标题：保留为文档元数据或标题上下文。
版本、生效日期、受控文件编号：必须保留。
密级、免责声明：按合规要求保留或单独标记。
```

核心原则是：从正文移除，不等于从知识系统删除。版本号不必在每个块反复出现，却必须能被检索过滤、引用展示和审计使用。

### 5. 标题、列表和章节路径

标题提供适用范围。若只把“申请时限为 7 天”单独向量化，系统不知道这是哪个商品、哪种规则。应尽量保留：

```text
售后政策 > 退款规则 > 活动商品特殊规则
```

列表常表达禁止、条件或步骤。例如“以下情况不支持退款”与后面的三项必须保持关系；如果删除编号和引导句，模型可能只看见三个孤立事实，忘了它们是禁止条件。

### 6. 脚注与例外是高风险内容

脚注通常小、靠边、容易被误判为噪声，但经常写着适用范围、生效时间、特别活动例外和术语定义。

```text
退款时限为签收后 7 天。*
* 特殊活动商品以活动页面规则为准。
```

删掉脚注后正文仍通顺，却已经产生错误泛化。正确做法是把脚注保留为结构块，并与引用它的正文、表格或章节建立关系。

### 7. OCR 错误的处理边界

OCR 常出现多余空格、数字字母混淆、标点丢失、表格线误识、印章混入正文。对于明显无意义的字符间空格，可做标准化；但日期、金额、合同号、税率、订单号不能靠字符串替换悄悄修正。

高风险字段应：保留原始识别结果和页码，记录置信度和异常标记，结合格式、上下文、业务规则或人工复核确认。系统宁可说“需要确认”，也不应把猜测写成事实。

### 8. 去重的层次

| 重复来源 | 处理思路 |
| --- | --- |
| 每页装饰页眉 | 从正文移除 |
| 隐藏文字层与 OCR 双份内容 | 技术性去重，保留来源记录 |
| 同文件重复上传 | 文件/内容指纹幂等处理 |
| 不同版本相同段落 | 保留版本关系，不合并成无版本内容 |
| 不同章节相同句子 | 不可仅按文字删除，适用范围可能不同 |

文字相同不等于业务上可互换。去重必须理解来源、版本和章节。

### 9. 清洗质量的验收

```text
自动：空文本、乱码比例、页数覆盖、异常重复、异常短长块。
结构：标题、页码、版本、脚注、列表、表格关系是否还在。
业务：抽查真实问题能否找到完整规则、条件和例外。
可追溯：任一清洗块能否回到原文件页和处理规则版本。
```

若清洗后无法支持“活动商品例外是什么”“政策何时生效”等关键问题，后面的 rerank 和模型无法真正补救。

## 常见误区

### 误区 1：清洗就是删空格、换行和特殊字符

不对。它们可能表达列表、表格、编号或版本；必须结合块类型与上下文。

### 误区 2：页脚都应该删除

不对。纯页码可移出正文，但版本、生效日期、密级和免责声明可能必须保留。

### 误区 3：大模型能整理得更流畅，就能替代原始解析

不对。模型可能漏限制、补事实。原文和模型整理结果必须分开保存，关键结论应能回页核验。

### 误区 4：清洗差能靠更强 embedding 修好

不对。embedding 只能表示已有输入，无法恢复已删除脚注或错误表格关系。

## 本节练习

### 练习 1：为什么版本号可以从正文移出，却不能从系统删除？

答案：版本号可能决定当前资料是否有效。它可作为文档或块元数据用于过滤、引用和审计，没必要反复污染每个正文块。

### 练习 2：为什么下面两种换行不能同样处理？

```text
退款申请需在签收后
7 天内提交。

以下情况不支持退款：
1. 商品已使用。
2. 超过申请期限。
```

答案：前两行通常是同段视觉换行，应合并；后面表达标题和列表边界，必须保留其层级与编号，否则禁止关系会被损坏。

### 练习 3：为什么日期和金额属于高风险 OCR 字段？

答案：一个字符误识就会改变结论，且看似合理的自动替换也可能改错原值。必须保留来源、做校验并按风险复核。

## 自测题

### 自测 1：规范化中间表示的价值是什么？

答案：它在原始解析和最终知识块之间保留结构、来源、处理版本和质量信息，支持检查、回滚、排错与重建。

### 自测 2：清洗最重要的原则是什么？

答案：先保真、再整洁；删除可确认的呈现噪声，保留可能影响业务解释、版本判断与来源追溯的内容。

### 自测 3：下一步分块前应确认什么？

答案：正文、标题、列表、脚注、页码、版本和表格关系已被合理保留，且关键业务问题能从清洗材料中获得完整证据。
