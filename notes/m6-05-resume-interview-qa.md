## 二、本节先不做什么

这一节不做这些事：

1. 不改业务代码。
2. 不新增接口。
3. 不启动服务。
4. 不跑真实模型。
5. 不做前端。
6. 不把简历写成最终投递版。
7. 不把项目包装成完整生产上线系统。

原因是：


## 三、基础知识铺垫

### 1. 什么是简历项目描述

简历项目描述是你在简历里写项目经历时使用的内容。

它通常包括：

```text
项目名称
项目背景
技术栈
你做了什么
解决了什么问题
有什么工程化亮点
项目结果或验证方式
```

简历项目描述不是完整文章。

它要短、准、可追问。

比如不要写：

```text
熟练使用 AI 技术开发智能系统。
```

这太空。

更好的写法是：

```text
基于 FastAPI + LangGraph 构建 AI 客服工单 Agent，支持知识库问答、订单查询、字段提取、用户确认和创建工单流程。
```

这句话有技术、有业务、有动作。

### 2. 简历里最忌讳什么

最忌讳三件事：

```text
夸大
空泛
堆名词
```

夸大：

```text
写成完整生产系统，但实际没有上线、没有真实数据库、没有认证授权。
```

空泛：

```text
写“负责 AI 项目开发，提高效率”，但没有说明做了什么。
```

堆名词：

```text
写 Java、Python、RAG、Agent、Docker、LangGraph、Milvus、CI，但没有说明这些技术在项目里负责什么。
```

当前项目最稳的表达是：

```text
AI 应用工程学习项目 / 作品原型。
```

这不弱。

因为它真实。

### 3. 为什么要准备多个讲稿版本

面试时，面试官给你的时间不固定。

可能说：

```text
简单介绍一下项目。
```

你可能只有 1 分钟。

也可能说：

```text
详细讲讲你的 Agent 项目。
```

你可能有 5 分钟。

如果只准备一个长版本，短时间讲不完。

如果只准备一个短版本，被追问时展开不了。

所以准备三种版本：

```text
1 分钟：项目总览
3 分钟：标准讲法
5 分钟：深入讲法
```

### 4. 1 分钟讲稿讲什么

1 分钟讲稿只讲最关键内容：

```text
项目是什么
核心技术
核心业务流程
工程化亮点
当前边界
```

不要讲太多细节。

1 分钟讲稿的目标是：

```text
让面试官知道这个项目值得继续追问。
```

### 5. 3 分钟讲稿讲什么

3 分钟讲稿可以展开：

```text
业务背景
整体架构
RAG
Agent 工单流程
工具调用安全
评测和生产化
边界和后续路线
```

这是最常用版本。

### 6. 5 分钟讲稿讲什么

5 分钟讲稿可以更深入：

```text
为什么这样设计
关键模块职责
数据流和控制流
技术取舍
测试和评测
生产化策略
后续真实化计划
```

5 分钟讲稿不是把所有笔记背一遍。

它要像工程复盘。

### 7. 什么是常见追问

常见追问是面试官听完项目后，最可能继续问的问题。

比如：

```text
为什么用 RAG？
为什么用 LangGraph？
Tool Calling 怎么保证安全？
怎么评测 Agent？
为什么测试不用真实模型？
项目离生产级还差什么？
```

提前准备追问，可以避免临场乱答。

### 8. 面试回答要有结构

回答技术问题时，不要一上来堆细节。

推荐结构：

```text
先直接回答。
再解释原因。
再结合项目。
最后说边界或取舍。
```

比如问：

```text
为什么用 LangGraph？
```

可以回答：

```text
因为这个项目不是单轮问答，而是多步骤、有状态、有分支、有人工确认的工单流程。LangGraph 可以把流程拆成节点和边，用 State 保存中间状态，用 checkpoint/thread_id 支持恢复。当前项目用它编排意图识别、RAG 回答、订单查询、字段提取、用户确认和创建工单。但当前还是单 Agent 业务流程，不是复杂 Multi-Agent 系统。
```

这个回答就比较完整。

### 9. 项目不足怎么讲

项目不足不要回避。

但也不要只说：

```text
还有很多不足。
```

要具体说：

```text
当前 Java 服务还是 mock，没有真实 Spring Boot + 数据库。
当前没有前端工作台。
当前没有真实部署和生产监控。
当前 eval dataset 规模还小。
```

然后补：

```text
下一阶段我会优先把 Java mock service 升级为真实 Spring Boot + MySQL/Redis。
```

这样不足就变成路线。

### 10. 面试里要避免的表达

不要说：

```text
我做了一个完整生产级 AI 客服系统。
```

不要说：

```text
这个项目已经可以企业上线。
```

不要说：

```text
我用 LangGraph 实现了复杂多智能体系统。
```

当前更准确的是：

```text
我做了一个 AI 客服工单系统学习项目和作品原型，重点展示 RAG、Tool Calling、LangGraph Agent、评测和生产化设计能力。
```

### 11. 简历材料必须和项目事实对应

简历和面试材料不是单独存在的。

它必须能回到项目事实。

也就是说，你在简历里写的每一句，最好都能在项目里找到对应证据。

比如你写：

```text
设计企业知识库 RAG 流程。
```

你要能指到：

```text
文档加载
chunk 切分
metadata
embedding
向量库写入
检索
引用来源
无上下文拒答
RAG eval
```

如果你写：

```text
使用 LangGraph 编排智能工单 Agent。
```

你要能讲清楚：

```text
State 保存什么
节点负责什么
边如何跳转
什么时候追问
什么时候确认
什么时候调用工具
什么时候结束
```

如果你写：

```text
补充稳定性保护。
```

你要能说出：

```text
timeout
retry
rate limit
circuit breaker
degradation
health/readiness
CI regression
```

这就是项目表达的基本原则：

```text
简历一句话 -> 项目一个模块 -> 面试一段解释 -> 代码或文档一个证据
```

你以后写任何项目，都可以按这个方式检查。

### 12. 面试追问背后其实在考什么

面试官追问一个问题，表面是在问技术点，实际通常在看四件事。

第一，看你是不是只会用。

比如问：

```text
为什么用 RAG？
```

如果只答：

```text
因为 RAG 可以检索知识库。
```

这个答案太浅。

更好的回答要包含：

```text
业务知识私有且变化快
模型本身不知道内部政策
检索可以降低编造
引用来源可以让回答可追溯
没有可靠上下文时应该拒答
```

第二，看你是不是知道边界。

比如问：

```text
为什么不能让模型直接创建工单？
```

背后其实在考：

```text
你是否知道模型输出不稳定
你是否知道写操作有风险
你是否知道后端应该掌握执行权
你是否知道用户确认和幂等的重要性
```

第三，看你是不是有工程化意识。

比如问：

```text
怎么评测 Agent？
```

背后其实在考：

```text
你是否只靠人工试
你是否知道 eval dataset
你是否知道 bad case
你是否知道 regression
你是否能区分 test 和 eval
```

第四，看你是不是诚实。

比如问：

```text
这个项目生产可用吗？
```

你要能准确说出：

```text
已经完成哪些能力
还缺哪些真实生产能力
下一步准备怎么补
```

这种回答比强行夸项目更可靠。

### 13. 答不出来的问题怎么处理

学习项目面试时，不可能所有问题都答得非常深。

遇到暂时不会的问题，不要乱编。

可以用这个结构：

```text
先承认边界
说出当前理解
结合项目说明做到哪一步
说明后续怎么继续补
```

例如面试官问：

```text
如果向量库数据量到千万级，你怎么优化？
```

如果你还没有真正做过千万级数据，可以这样答：

```text
我还没有在真实千万级数据上做过压测。当前项目主要在本地学习 Qdrant 和 Milvus 的基本检索链路，理解了 collection、vector、payload、index、top_k、score_threshold 和 filter。我的下一步会从索引类型、分片、副本、冷热数据、批量写入、查询延迟、召回率评测和监控指标几个方面继续补，并通过压测数据判断优化效果。
```

这比假装做过更好。

因为它说明你知道：

```text
自己做到哪
问题应该从哪些方向拆
下一步怎么验证
```

```text
构建
```


### 5. 1 分钟讲稿怎么用

```text
面试开场
```

### 8. 常见追问怎么准备

常见追问要覆盖 5 类：

```text
RAG
Agent / LangGraph

评测和测试
生产化和后续路线
```

这五类基本覆盖 AI Agent 开发作品最常见问题。

### 9. 简历 bullet 和项目模块怎么对应

简历里的每条 bullet 都不应该是孤立的。

本项目可以这样对应：

```text
FastAPI AI 服务
-> 对应 projects/ai-service
-> 能讲 API 分层、Pydantic、异常处理、日志、测试

RAG 企业知识库问答
-> 对应 RAG 笔记、知识库文档、Qdrant/Milvus 学习内容
-> 能讲 chunk、metadata、embedding、检索、引用、拒答、eval

LangGraph 智能工单 Agent
-> 对应 Agent 状态图和工单流程
-> 能讲 State、node、edge、checkpoint、thread_id、追问、确认

Tool Calling 安全边界
-> 对应工具注册、参数校验、读写区分、用户确认、幂等键
-> 能讲为什么模型只提出意图，后端才执行

Agent eval 和 regression
-> 对应评测数据集、evaluator、bad case、回归脚本
-> 能讲为什么 AI 项目不能只靠手工试

生产化设计
-> 对应日志、trace、metrics、timeout、retry、限流、熔断、降级、CI
-> 能讲系统出问题时怎么定位、怎么保护
```

这样准备的好处是：面试官追问任何一条，你都能顺着项目真实内容继续展开。

### 10. 讲项目时要控制层次

讲项目不要一口气把所有技术名词倒出来。

建议按三层讲：

```text
第一层：业务目标
第二层：核心链路
第三层：工程保障
```

业务目标：

```text
客服问答、订单查询、创建工单
```

核心链路：

```text
RAG
Tool Calling
LangGraph Agent
Java mock service
```

工程保障：

```text
Pydantic 校验
用户确认
eval
trace/log/metrics
timeout/retry/限流/熔断/降级
Docker Compose
CI
```

这个层次能让别人听懂你不是在堆技术，而是在围绕业务问题组织技术。

### 11. 常见追问应该按“考点”准备

不要只背一问一答。

每个追问都要知道它背后的考点。

例如：

```text
为什么用 LangGraph？
```

考点不是 LangGraph 名字，而是：

```text
你是否理解多步骤流程
你是否理解状态管理
你是否理解分支跳转
你是否理解中断和恢复
```

再比如：

```text
怎么评测 Agent？
```

考点不是会不会说 eval，而是：

```text
你是否能把 AI 效果拆成可检查的维度
你是否知道坏例分析
你是否知道回归
你是否知道测试和评测的区别
```

再比如：

```text
项目离生产还差什么？
```

考点是：

```text
你是否诚实
你是否知道真实系统需要数据库、认证、事务、部署、监控
你是否知道下一步学习路线
```

## 五、本节练习

### 练习 1：简历项目描述最忌讳什么？

参考答案：

```text
最忌讳夸大、空泛和堆名词。不能把学习项目写成完整生产上线系统，也不能只写一堆技术名词却不说明这些技术在项目中解决什么问题。
```

### 练习 2：为什么要准备 1/3/5 分钟讲稿？

参考答案：

```text
因为面试中可用时间不固定。1 分钟用于快速总览，3 分钟用于标准介绍，5 分钟用于深入展开。这样可以根据面试官节奏灵活讲，而不是只背一个版本。
```

### 练习 3：当前项目最稳的简历定位是什么？

参考答案：

```text
企业知识库 RAG + 智能工单 Agent 系统，定位为 AI 应用工程学习项目和作品原型，不是完整生产上线系统。
```

### 练习 4：项目不足怎么讲才专业？

参考答案：

```text
要具体说明当前还缺真实 Spring Boot 业务服务、真实数据库、认证授权、前端工作台、线上部署和生产监控，然后说明下一阶段会优先补真实 Java Spring Boot + MySQL/Redis。
```

### 练习 5：面试追问“为什么测试不用真实模型”怎么答？

参考答案：

```text
真实模型有成本、网络、API Key 和输出不稳定问题，不适合作为所有自动化测试的基础依赖。项目中用 fake LLM 和规则 evaluator 做稳定回归，真实模型放在受控 smoke 或人工验证中。
```
