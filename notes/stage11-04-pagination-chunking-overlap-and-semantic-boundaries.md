# M11 第 4 节：分页、分块、重叠与语义边界

## 本节定位

PDF 已经被解析、清洗并恢复了基本结构。下一步不是随手按 500 字切开，而是设计 RAG 最重要的证据单位：一个文本块应当包含什么，才能既容易被问题检索到，又不会把规则、条件和例外拆坏？

## 本节学习目标

1. 区分页、结构块、检索块、回答上下文和引用范围。
2. 理解语义边界为何比固定长度重要。
3. 比较固定长度、递归、结构化、语义、父子分块策略。
4. 分清 `chunk size`、`overlap`、`top_k` 的职责。
5. 根据 FAQ、政策、流程和表格选择分块方法。
6. 用失败回答反向判断分块问题。

## 一句话先讲透

**分块不是把长文本变短，而是把原文加工成“能够独立支持一个可核验结论，并保留必要上下文”的证据单位。**

## 基础知识铺垫

### 1. 页不是块

页是 PDF 为展示和打印设计的视觉单位；块是 RAG 为检索设计的语义单位。

```text
一条规则可以只占半页。
一个完整流程可以跨两页。
一页可能同时包含两个无关章节。
一张表可跨很多页。
```

因此常见做法是：页码用于来源定位，块用于检索。一个块可关联一页或页码范围，一页也可产生多个块。

### 2. 为什么需要分块

不能把所有文档直接交给模型：上下文有限，成本和延迟会上升，无关内容还会稀释注意力。检索也需要明确候选单位。

分块的目标不是“缩短文本”，而是同时让内容：

```text
可向量化、可检索、可重排。
可单独解释，不脱离主语、条件和例外。
可组合成模型上下文。
可回到文档、版本、页码和章节引用。
```

### 3. 字符、token 与语义不是同一尺度

字符是文字和标点；token 是模型编码单位；语义边界是一个意思相对完整的结束位置。用字符或 token 限制长度是必要工程约束，但它们不能自动找到规则的逻辑边界。

例如“退款时限为签收后 7 天，但活动商品除外”即使很短，也不应在“但”后切开；否则检索到前半句时会产生错误结论。

## 本节主题系统讲解

### 1. 四个互相拉扯的目标

| 目标 | 含义 | 过度追求会怎样 |
| --- | --- | --- |
| 语义完整 | 条件、结论、例外、主语足够完整 | 块可能变大 |
| 检索精度 | 一个块主题聚焦 | 块过小会断上下文 |
| 上下文经济性 | 适合模型输入、成本和延迟 | 块过短可能证据不足 |
| 可追溯性 | 能定位来源、页码和章节 | 需要更多结构元数据 |

不存在所有材料通用的最佳长度。正确问题是：对这类资料与问题，一个结论最少需要带哪些内容才不会误导人？

### 2. 固定长度分块

按字符、词或 token 到达上限就切。优点是简单、稳定、适合无结构纯文本的基线；缺点是不了解标题、段落、条款、表格和例外。

它更适合作为兜底：当一个结构块过长时，再在较小自然边界上拆分，而不应成为第一边界。

### 3. overlap 的真正作用

相邻块共享少量内容，能缓解概念刚好跨边界的问题。

```text
块 A：第 1-500 字
块 B：第 451-950 字
```

但 overlap 不能：修复错误阅读顺序、恢复表格行列、保证远距离例外同块出现，或让无结构文本自动变正确。过大 overlap 还会制造近似重复块，提高成本、降低召回多样性。

### 4. 三个常被混淆的参数

```text
chunk size：单个块最大长度。
overlap：相邻块重复多少内容。
top_k：查询时取多少候选块。
```

增大 `top_k` 不能修复块中缺失的例外；增大 overlap 也不能代替召回与重排。调参前必须先确认问题属于哪一层。

### 5. 递归分块

递归策略优先按大结构切，再逐级退化：

```text
章节 -> 段落 -> 句子 -> 字符边界
```

它尊重自然结构，同时限制超长内容，适合普通文档的默认起点。前提是上游清洗保留了可靠标题和段落；若结构已错，递归只会在错文本上切得更整齐。

### 6. 结构化分块

让内容类型决定边界：

| 内容 | 自然分块单位 |
| --- | --- |
| FAQ | 一个问题与其完整答案 |
| 政策条款 | 条款、适用条件、例外、章节路径 |
| 操作手册 | 一个目标的完整前置条件、步骤与注意事项 |
| 表格 | 表名、表头、一行或相关行、单位与脚注 |
| 目录 | 导航信息，通常不作为普通答案证据 |

结构化分块最接近人类理解，但依赖解析和版面恢复质量。

### 7. 语义分块

语义分块关注主题变化，例如从“退款条件”转向“退款时效”或“运费责任”时再切。它可借助标题、规则或相似度判断。

优点是贴近内容；缺点是边界判断可能不稳定、成本较高、难复现。实践上先用“结构优先 + 长度上限”的稳定策略，再用评测证明是否值得引入更复杂的语义判断。

### 8. 父子分块与上下文补全

检索需要小而精确的块，回答需要完整上下文，这两个目标可以分开：

```text
子块：活动商品退款申请时限，用于精确召回。
父块：活动商品整节规则、例外和说明，用于模型回答。
```

标题、章节路径也可作为轻量上下文加入块：

```text
售后政策 > 退款规则 > 活动商品
申请时限为签收后 7 天。
```

这不是编造信息，而是把原文已有的关系显式保留。父子关系、相邻块关系和页码范围需作为元数据记录。

### 9. 特殊材料的判断

```text
FAQ：问题和答案不要拆开。
政策：规则、条件、例外、生效信息尽量在同一证据范围。
流程：一个任务的完整步骤和注意事项一起保留。
表格：表头、单位、数据行和注释保持关系。
跨页内容：分页不是硬边界，用章节或表格 ID 关联。
```

分块不是只面向文档，而是面向未来用户会怎样提问。

### 10. 如何用症状排错

| 现象 | 更可能的原因 |
| --- | --- |
| 总答出规则，漏掉例外 | 规则与例外被拆开，或上下文补全缺失 |
| 召回相关但混入很多主题 | 块过大或结构混杂 |
| 大量相邻重复证据 | overlap 过大或去重不足 |
| 表格题总字段错位 | 表格解析/分块破坏了关系 |
| FAQ 答案偏题 | 问题与答案被拆开 |
| 输入很长且成本高，效果不稳定 | 块过大、top_k 过高或证据选择差 |

不要先换模型。先定位是结构、分块、检索、上下文还是生成问题。

### 11. 分块质量怎样验证

使用专门问题检查：

```text
规则是什么？它适用于谁？例外是什么？
两个相似规则差异是什么？
某表格行对应的责任方与单位是什么？
跨页条款能否找到完整上下文？
```

比较不同策略时，固定同一资料、embedding、检索与问题集，观察正确证据是否命中、条件例外是否完整、引用是否准确、成本延迟如何变化。块数和平均长度不是质量指标。

## 常见误区

### 误区 1：每 500 字是行业标准

不对。它只是起点，不同文档、语言、风险与检索方式需要不同边界。

### 误区 2：块越小，检索一定越准

不对。过小会丢主语、条件、例外，得到“半句话命中”的伪精确。

### 误区 3：块越大，回答一定越完整

不对。过大混入无关主题，增加成本并稀释模型注意力。

### 误区 4：top_k 能修复分块问题

不对。多取候选不能恢复已丢失的语义关系，反而可能带来更多噪声。

## 本节练习

### 练习 1：页与块的区别是什么？

答案：页是 PDF 的视觉展示单位；块是 RAG 的语义检索单位。一个块可跨页，一页可有多个块，页码主要用于来源定位。

### 练习 2：chunk size、overlap、top_k 各控制什么？

答案：chunk size 控制单块长度；overlap 控制相邻块共享内容；top_k 控制查询取回的候选数量。三者不能互相替代。

### 练习 3：父子分块解决什么矛盾？

答案：用小子块提高检索精度，用大父块提供完整回答上下文，解决“块小易断关系、块大不易精确检索”的矛盾。

## 自测题

### 自测 1：什么是语义边界？

答案：一个内容单元相对完整、可独立理解的位置，例如一条规则连同适用条件和例外，一个完整 FAQ，或一组完整操作步骤。

### 自测 2：为什么标题与章节路径常需进入检索材料？

答案：正文单独出现时可能没有主题和适用范围。它们为块提供原文已有的必要上下文，提高检索、回答和引用质量。

### 自测 3：本节最重要的结论是什么？

答案：分块是证据设计，不是机械切字符。它必须平衡语义完整、检索精度、上下文经济性和来源可追溯。
