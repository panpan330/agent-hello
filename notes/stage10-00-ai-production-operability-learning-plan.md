# 阶段 10 学习计划：AI 应用生产化与可运营能力

## 阶段定位

阶段 10 的主题是：

```text
AI 应用生产化与可运营能力
```

前面几个阶段已经完成了很多关键能力：

```text
Python AI 服务
FastAPI
LLM API 调用
Structured Output
Tool Calling
Agent Loop
LangGraph
RAG
Embedding
Qdrant / Milvus
MCP
真实 Java Spring Boot + MyBatis + MySQL/Redis 业务服务
RAG 进阶与检索质量优化
```

现在项目已经不缺“AI 功能点”。

阶段 10 要解决的是另一个问题：

```text
一个 AI 应用怎么从能跑、能演示，继续走向稳定、安全、可观测、可评估、可控成本、可灰度上线的真实工程系统。
```

换句话说，阶段 10 不只是继续加功能，而是补真实工作中非常重要的一层：

```text
运行治理能力
```

## 为什么阶段 10 学这个

一个 AI 应用在本地能跑通，只能说明功能可用。

真实系统还会遇到这些问题：

```text
用户请求变多后会不会慢？
模型 API 超时怎么办？
模型回答失败怎么办？
备用模型怎么切？
一个用户疯狂请求怎么限制？
一次请求到底花了多少 token？
成本超过预算怎么办？
日志能不能排查一次失败？
日志会不会泄露用户隐私和 API Key？
流式输出中途失败怎么处理？
Prompt Injection 怎么继续加固？
线上效果变差怎么发现？
Bad Case 怎么收集和回归？
新版本怎么灰度发布？
上线失败怎么回滚？
服务可用性目标怎么定义？
出问题时新人按照什么文档排查？
```

这些问题不属于“模型会不会回答”，而属于“AI 应用能不能稳定运行”。

阶段 10 就是专门补这块。

## 阶段目标

学完阶段 10 后，目标不是只会说：

```text
我会调用大模型。
我会做 RAG。
我会写 Agent。
```

而是能进一步说清楚：

```text
我知道 AI 应用上线后怎么追踪、怎么评估、怎么控成本、怎么限流、怎么重试、怎么超时、怎么降级、怎么做流式输出、怎么保护密钥和隐私、怎么灰度发布、怎么回滚、怎么写 runbook。
```

更具体地说，要达到这些能力：

- 能解释 tracing、trace_id、span、event、metric 的区别。
- 能给 Python AI 服务和 Java 业务服务设计统一追踪链路。
- 能安全记录 LLM 调用日志，不泄露密钥、隐私和完整敏感上下文。
- 能统计 token 成本，并理解成本为什么会失控。
- 能拆解一次 AI 请求的耗时组成。
- 能实现或设计多模型路由和模型 fallback。
- 能设计预算、限额、降级策略。
- 能区分限流、重试、超时分别解决什么问题。
- 能把 SSE 流式输出做得更接近生产使用。
- 能强化 Prompt Injection、权限和模型输出安全。
- 能建立自动化评估、评测集版本、bad case 回归的闭环。
- 能设计线上监控指标和告警规则。
- 能解释灰度发布、回滚、SLO、SLA、Runbook。
- 能把这些内容讲成面试中的 AI 应用生产化经验。

## 阶段 10 固定 28 节

| 节 | 主题 | 目标 |
| --- | --- | --- |
| 1 | AI 应用生产化总览 | 建立阶段 10 的完整地图，理解 AI 应用从 demo 到真实系统之间差哪些工程能力 |
| 2 | Tracing 是什么 | 理解为什么 AI 应用必须能追踪一次请求从入口到模型、RAG、Tool、Java 后端的完整链路 |
| 3 | trace_id / span / event / metric 的区别 | 区分链路标识、阶段片段、关键事件和聚合指标，避免把日志、trace、metric 混成一件事 |
| 4 | Python AI 服务 tracing | 在 ai-service 内部梳理请求入口、LLM 调用、RAG、rerank、Tool 调用等节点的追踪方式 |
| 5 | Java 业务服务 tracing 对齐 | 理解 Python 调 Java 时如何传递 trace_id，并让 Java 日志、错误码和响应头能串联排查 |
| 6 | LLM 调用日志安全 | 学习 LLM 请求、响应、错误、耗时、模型名、token 记录时如何避免泄露密钥、隐私和完整敏感上下文 |
| 7 | 配置与密钥管理 | 系统学习 `.env`、`.env.example`、不同环境配置、API Key 管理、密钥不上 GitHub、配置分层和最小暴露 |
| 8 | Token 成本统计 | 理解 prompt tokens、completion tokens、总 token、单次成本、累计成本和按用户/模型/接口统计成本 |
| 9 | 请求耗时拆解 | 学习把一次请求拆成检索、rerank、LLM、Tool、Java 后端、序列化等耗时阶段 |
| 10 | 多模型路由基础 | 理解为什么一个 AI 系统可能需要按任务类型、成本、速度、稳定性选择不同模型 |
| 11 | 模型 fallback | 学习主模型失败、超时、限流或质量不稳定时如何切备用模型，以及 fallback 的边界 |
| 12 | 成本控制 | 学习预算、限额、上下文裁剪、降级、缓存、低成本模型和高成本能力开关 |
| 13 | 限流 | 区分用户级、接口级、模型级、工具级限流，理解限流和权限、成本、稳定性的关系 |
| 14 | 重试 | 学习哪些错误可以重试、哪些不能重试，读操作和写操作重试边界，以及幂等要求 |
| 15 | 超时治理 | 设计请求总超时、模型超时、检索超时、工具超时、Java 后端超时和降级策略 |
| 16 | SSE 流式输出生产化 | 学习流式响应的价值、事件格式、心跳、首 token 延迟、客户端体验和服务端资源占用 |
| 17 | 流式错误处理和中断 | 学习流式输出中途失败、用户取消、上游超时、部分内容已输出时如何处理 |
| 18 | Prompt Injection 防护强化 | 在 RAG 防护基础上继续学习系统提示、工具调用、外部输入和多轮上下文中的注入风险 |
| 19 | 权限控制强化 | 系统梳理用户、租户、角色、权限组、工具权限、读写权限和后端最终授权边界 |
| 20 | 模型输出安全与隐私保护 | 学习敏感信息、个人隐私、日志脱敏、回答边界、拒答策略和安全输出过滤 |
| 21 | 自动化评估平台基础 | 从脚本式 eval 走向可持续评估，理解评测任务、评测数据、评测结果和报告沉淀 |
| 22 | 评测集版本管理 | 学习评测集为什么要版本化，如何区分新增 case、修改 case、废弃 case 和回归基线 |
| 23 | Bad Case 收集和回归测试 | 学习线上 bad case 如何进入评测集，如何防止修好一个问题又破坏旧问题 |
| 24 | 线上监控指标设计 | 设计 AI 服务需要观察的请求量、错误率、延迟、token、成本、模型失败、fallback、限流等指标 |
| 25 | 告警 | 学习什么时候应该报警，如何避免告警太少漏问题或告警太多没人看 |
| 26 | 灰度发布与回滚 | 学习 AI 功能、Prompt、模型、RAG 参数和路由策略如何灰度发布，失败后如何回滚 |
| 27 | SLO / SLA / Runbook | 理解服务目标、对外承诺和故障处理手册，知道出问题时如何按步骤排查和恢复 |
| 28 | 阶段 10 总复盘和面试表达强化 | 把阶段 10 的生产化能力整理成项目表达、面试回答、简历素材和后续路线 |

## 阶段学习边界

阶段 10 会重点学 AI 应用生产化，但不会一次性深入所有平台级技术。

本阶段会学：

```text
Tracing 基础
日志安全
token 成本
耗时拆解
多模型路由
fallback
成本控制
限流
重试
超时
SSE 生产化
Prompt Injection 加固
权限强化
隐私保护
自动化评估
评测集版本
Bad Case 回归
监控指标
告警
灰度
回滚
SLO / SLA / Runbook
```

本阶段暂不作为主线深入：

```text
Kubernetes 大规模部署
完整 APM 平台搭建
Prometheus / Grafana 深度运维
LangSmith 商业平台深度使用
复杂多租户计费系统
大规模评测平台前端
模型微调
自建推理服务集群
多 Agent 大规模协作平台
```

这些不是不重要，而是当前阶段先补 AI 应用工程化的核心思想和项目落地方式。

## 阶段默认学习方式

阶段 10 继续沿用当前学习要求：

- 每节笔记必须保证高质量，不能薄。
- `基础知识铺垫` 和 `本节主题系统讲解` 是重点。
- `本节定位`、`学习目标`、`新增和修改`、`一句话先讲透` 保持简洁。
- 如果有代码，代码只服务学习目标，不为了堆功能而写。
- 测试只讲关键点，不大篇幅讲测试实现细节。
- 练习题和自测题答案放在对应题目下面。
- 纯知识节不生成 manual-tasks 文档。
- 只有涉及真实服务、curl、Docker、数据库、Redis、Qdrant、Milvus、VMware、`.env` 手动配置时，才考虑 manual-tasks。
- 平时不做敏感扫描，上传 GitHub 前再做。
- 不默认更新 `projects/java-business-service/README.md`。

## 环境说明

阶段 10 默认不需要每节都打开 VMware Ubuntu。

默认情况：

```text
Windows 本地即可。
不需要真实调用大模型。
不需要 Qdrant / Milvus。
不需要启动 Java business service。
不需要启动 Redis / MySQL。
```

可能需要真实服务的章节：

```text
Java 业务服务 tracing 对齐
真实 Redis 限流或缓存验证
真实 MySQL / Java 后端错误排查
SSE 本地手动体验
真实模型 fallback 或 token 成本观察
```

如果某一节需要打开虚拟机、启动 Docker、启动 Redis/MySQL、启动 Java 服务或配置真实模型 API，开始前必须明确告诉用户。

```text
在 AI 应用生产化方面，我不只关注模型调用和 RAG/Agent 功能本身，还补充了 tracing、日志安全、token 成本统计、请求耗时拆解、多模型路由、模型 fallback、限流、重试、超时、SSE 流式输出、Prompt Injection 防护、权限控制、隐私保护、自动化评估、bad case 回归、线上监控、告警、灰度发布、回滚和 runbook。这样 AI 应用不仅能跑通，还能被观测、被评估、被控制成本、被安全上线和持续运营。
```


## 阶段 10 第一节

第一节从这里开始：

```text
阶段 10 第 1 节：AI 应用生产化总览
```

这一节主要解决：

- 什么是 AI 应用生产化。
- 为什么能跑通不等于能上线。
- AI 应用比传统后端多了哪些生产风险。
- 阶段 10 的 28 节分别补哪些能力。
- 当前项目哪些已有能力可以复用。
- 学完阶段 10 后项目表达会提升到什么程度。

这一节默认不需要打开虚拟机，不需要启动外部服务，不需要真实调用模型。
