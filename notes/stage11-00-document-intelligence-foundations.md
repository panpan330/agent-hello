# M11 阶段前置基础：企业文档智能与知识工程

## 为什么先学这一篇

M11 不是“把 PDF 切块放向量库”的工具课。它要解决的是：企业里原本只供人阅读的制度、合同、手册、表格和扫描件，如何成为 AI 能够安全使用、用户能够核验、团队能够长期维护的知识。

如果没有这个阶段基础，后面的 OCR、分块、元数据、权限和引用会变成一串操作步骤。流程能运行，不代表知识可靠。真正危险的问题往往是：

```text
文件更新后，系统仍引用旧版本。
规则的例外藏在脚注，却在解析或分块时丢失。
表格的单位和行列关系损坏，金额结论被解释错。
无权资料进入模型上下文。
回答听起来合理，却无法回到具体版本和页码核验。
```

这篇笔记建立 M11 的共同语言。后续每节都应能回答：它保护了什么事实或关系？它处于哪条链路？失败后如何发现和恢复？

## 学习目标

读完后，你应能：

1. 解释数据、信息、知识与证据的差别。
2. 区分业务数据库、文档库、向量索引与大模型的职责。
3. 说清原始文件、解析结果、知识块、向量和回答之间的关系。
4. 画出离线加工、在线问答、知识治理三条链。
5. 判断企业文档 RAG 的正确性、安全性与可维护性来自哪里。

## 一句话先讲透

**企业文档 RAG 的本质，是把原始资料加工成有来源、有结构、有版本、有权限的证据，让模型只在这些证据范围内解释。**

## 基础知识铺垫

### 1. 数据、信息、知识、证据

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 数据 | 原始记录，未必带完整背景 | 一个 PDF、数字 `7`、一行表格 |
| 信息 | 已处于某个语境中的数据 | “退款时限为 7 天” |
| 知识 | 可组织、复用和解释的信息体系 | 完整退款政策、适用范围和例外 |
| 证据 | 可追溯、可核验、能支持结论的知识片段 | 2026.08 版政策第 4 页第 3.2 节 |

模型回答“活动商品可退款”只是一个结论。只有同时知道它依据什么版本、哪个章节、有哪些条件和例外时，才构成可被企业使用的证据链。

### 2. 结构化、半结构化与非结构化数据

结构化数据有固定字段，例如订单号、金额、状态、签收时间，适合数据库精确查询与事务处理。半结构化数据有标签或层级，例如 JSON、HTML、Markdown。非结构化数据如 PDF、扫描件、图片和邮件正文，结构主要供人阅读，机器不能直接稳定使用。

PDF 并不是“没有结构”，而是它的标题、段落、表格、双栏、页脚和脚注通常没有以稳定逻辑字段保存。人看见的是一页规则；程序可能只看见不同坐标上的字符和图片。文档智能的工作就是恢复足够可信的结构和关系。

### 3. 原始文件、解析结果、知识块、向量和回答

```text
原始文件：事实来源，可供人工核验、审计和重新处理。
解析结果：程序从文件中读出的文字、区域、表格和布局，可能有误。
知识块：带标题、页码、版本、权限等上下文的检索证据单位。
向量索引：知识块的相似度检索副本，可随模型和规则变化重建。
模型回答：一次基于证据生成的解释，不是新的事实来源。
```

这五者不能互相替代。向量不能恢复精确原文，模型回答也不能覆盖版本治理；原始文件与处理记录才是最终可回溯的基础。

### 4. 业务数据库、文档知识库和模型如何协作

| 组件 | 负责什么 | 不应负责什么 |
| --- | --- | --- |
| 业务数据库 | 订单状态、金额、用户等当前确定事实 | 长篇制度解释 |
| 文档库 | 原文件、版本、审批、权限和生命周期 | 语义相似度检索 |
| 向量/全文索引 | 从大量资料中找候选证据 | 原始真相和授权决策 |
| 大模型 | 基于证据解释、归纳、拒答 | 访问控制、版本判断、编造事实 |

例如“我的订单能否退款”必须同时使用：政策文档中的规则、订单数据库中的商品类型与签收时间、认证系统中的用户身份。模型负责组织回答，不能自行猜测订单事实或替代业务规则。

## 本节主题系统讲解

### 1. 三条核心链路

#### 离线知识加工链

```text
接收文件
-> 校验来源、格式、权限与状态
-> 文本提取 / OCR / 版面恢复
-> 清洗与结构化
-> 分块与元数据构建
-> 向量化和索引
-> 质量检查
-> 发布为可检索版本
```

它的目标是“把资料做对”。解析失败、OCR 低置信度或权限字段缺失的资料，应进入失败或人工复核状态，而不是假装已可用。

#### 在线问答链

```text
可信用户身份 + 用户问题
-> 租户、角色、状态、有效期硬过滤
-> 关键词/向量召回
-> 重排、去重与上下文补全
-> 选择足够证据
-> 模型基于证据回答
-> 返回版本、页码、引用和边界说明
```

它的目标不是找最多资料，而是让当前用户只接触当前有效、真正相关、自己有权看到的证据。

#### 知识治理链

资料会更新、失效、删除；权限会变化；解析和 embedding 规则也会升级。治理链负责版本、有效期、删除、重建、评估、审计和 bad case 回归。没有它，系统会逐渐积累过期、重复、无权的幽灵知识。

### 2. 一个贯穿案例

企业要做“售后政策助手”。资料有《售后政策 2026.08》，其中规定普通商品、活动商品和跨境商品的退款规则。

错误做法是：PDF 转文本，每 500 字切一段，算向量，取三段让模型回答。它会导致活动例外被切到下一块、表格列错位、旧版本与新版本一起召回，或者普通客服看到内部跨境规则。

正确做法是：

```text
保留原始文件和生效版本。
诊断文字层、扫描页、表格和脚注。
恢复章节，例如“退款规则 > 活动商品特殊规则”。
让规则、条件和例外形成可引用证据块。
为每块保存页码、版本、权限、状态和内容指纹。
查询时先做权限、状态和有效期过滤。
模型只用已授权证据回答并展示出处。
新版本验证后切换，旧版本退出默认检索。
错误案例进入评测集，防止回归。
```

两种方案都可能生成流畅回答，但只有后者是在构建可信知识系统。

### 3. 文档 RAG 的六项质量

| 质量 | 要求 |
| --- | --- |
| 事实保真 | 条件、例外、单位、表格和脚注不能被悄悄改坏 |
| 检索相关 | 召回真正支持问题的证据，不是只含相似词的段落 |
| 可追溯 | 能定位到文档、版本、页码、章节或表格位置 |
| 权限正确 | 无权资料不召回、不进入模型上下文 |
| 生命周期正确 | 更新、失效、删除后在线范围保持一致 |
| 不确定性可见 | 证据不足、冲突或解析低质量时明确边界 |

任何只评价“回答是否自然”的方案，都遗漏了企业文档系统的大部分风险。

### 4. 单一真相来源

单一真相来源不是所有数据只放一个地方，而是每类事实有明确权威：

```text
政策内容与版本：受控原始文档和发布记录。
订单状态：业务数据库。
用户身份与角色：认证授权系统。
检索向量：由受控资料派生的索引副本。
模型回答：一次可追溯解释，不是长期权威。
```

当向量库的旧块与文件管理中的当前版本冲突时，应相信版本治理规则和原始资料，不能让模型或相似度分数决定事实。

### 5. 不确定性不是失败

可靠系统应该能说：

```text
该页 OCR 质量不足，需要人工确认。
当前资料无法确认这个结论。
两份有效资料存在冲突，需要按业务规则处理。
当前账号无权访问这类资料。
```

把不知道说清楚，比从残缺证据中生成确定答案更专业。后续每一节都会学习如何让这种边界在系统层面真正生效。

## 常见误区

### 误区 1：企业 RAG 就是把 PDF 放进向量库

不对。它至少包含文件、解析、结构、块、元数据、权限、版本、索引、回答和治理。

### 误区 2：模型回答自然就说明知识正确

不对。语言流畅不能证明版本、适用范围、页码、权限和证据完整性正确。

### 误区 3：文档入库后不用维护

不对。文档、权限、模型、分块规则和用户问题都会变化，治理是持续工作。

### 误区 4：OCR、向量库和模型能替代业务规则

不对。它们分别负责识别、召回和表达；权限、审批、实时业务事实与法律效力仍要由受控系统和人负责。

## 本篇练习

### 练习 1：解释原始文件、知识块、向量和模型回答的关系。

答案：原始文件是事实来源；知识块是从原文加工出的、带来源和结构的检索证据；向量是知识块的相似度表示；模型回答是根据当次证据生成的解释，不能替代事实来源。

### 练习 2：为什么“订单能否退款”不能只靠 RAG 回答？

答案：政策文档只能提供规则，订单的商品类型、签收时间和状态来自业务数据库；最终还要根据权限和业务规则判断。RAG、数据库和模型需协作。

### 练习 3：请解释三条核心链路。

答案：离线加工链把文件变成可检索证据；在线问答链在有效且有权限的证据中回答；治理链负责版本、删除、评估、审计和长期一致性。

## 自测题

### 自测 1：为什么向量索引不是单一真相来源？

答案：它由原文、分块策略和 embedding 模型派生，可重建，也不包含完整版本、页码和授权语义。权威来源应是受控资料和业务管理记录。

### 自测 2：企业文档 RAG 的核心质量有哪些？

答案：事实保真、检索相关、可追溯、权限正确、生命周期正确，以及让不确定性可见。

### 自测 3：本篇最重要的结论是什么？

答案：企业文档 RAG 是证据加工与治理系统，模型只能在已授权、当前有效、可追溯的证据范围内工作。

## 小结

```text
PDF 与 OCR：把内容读出来。
清洗与分块：把内容组织成证据。
元数据与权限：决定证据的来源、范围和可见性。
检索与重排：找到证据。
引用与评估：证明、检查并持续改进证据链。
版本与删除：让知识长期保持正确。
```

后续 M11 每节都应放回这张全景图中理解，而不是只记工具和参数。
