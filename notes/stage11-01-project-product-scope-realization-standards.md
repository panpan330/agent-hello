# 阶段 11 第 1 节：项目产品范围与真实化标准

## 本节定位

阶段 11 开始后，主线从“学技术点”切换为“做完整项目”。

所以第一节不急着写代码。原因很简单：项目越完整，越需要先把范围和标准说清楚。否则后面很容易出现三个问题：

- 功能越加越散，不知道主线是什么。
- 有些地方该真实化却继续 mock。
- 有些地方不该现在做，却提前消耗大量时间。

本节的核心产出是：

```text
docs/stage11-product-scope-and-realization-standards.md
```

它会作为阶段 11 的项目边界文档。

## 本节解决的问题

本节主要回答：

- 完整智能工单系统到底是什么。
- 阶段 11 做完后，什么才算完整项目。
- 哪些东西必须使用真实组件。
- 哪些东西可以先简化。
- 前端、Java、Python AI、MySQL、Redis、Qdrant、真实模型分别负责什么。
- 项目包含哪些角色、页面、业务模块和关键流程。
- 后续阶段 11 应该按什么顺序推进。

## 项目真实化的核心标准

阶段 11 的目标不是“看起来像项目”，而是要做到核心链路真实可运行。

必须真实化的部分：

- 真实前端页面。
- 真实 Java Spring Boot 业务服务。
- 真实 MySQL。
- 真实 Redis。
- 真实 Python FastAPI AI 服务。
- 真实 LLM。
- 真实 embedding。
- 真实 rerank。
- 真实 Qdrant 向量数据库。
- 真实订单、工单、知识库和 AI 对话主流程。

可以先简化的部分：

- 企业 SSO。
- Kubernetes。
- 大规模压测。
- 支付、短信、邮件。
- 复杂多租户计费。
- 完整 APM 平台。

## 为什么这一节不写代码

这节不写代码不是因为它不重要，恰恰相反，它是阶段 11 的地基。

完整项目开发前，至少要先明确：

```text
做什么
不做什么
谁使用
有什么页面
有什么流程
什么叫完成
什么必须真实
什么可以后补
```

如果这些不清楚，后面就算写很多代码，也可能变成一堆功能片段，而不是一个能演示、能讲清楚、能写简历的完整项目。

## 后续推进方式

阶段 11 后续会按项目推进，不再按纯知识点推进。

大致顺序：

```text
产品范围
-> 技术方案和任务拆分
-> 前端项目骨架
-> 登录和角色
-> Java 业务模型补全
-> 前端订单/工单页面
-> AI 对话接口整理
-> 知识库真实入库
-> 真实模型链路验收
-> 端到端联调
-> 工单工作台
-> 评估和 bad case 页面
-> 运行部署文档
-> 演示和简历材料
-> 总验收
```

如果某一节需要你注册模型平台、准备 API Key、打开 VMware、启动 Docker、启动 MySQL/Redis/Qdrant，我会在开始前明确告诉你。

## 本节练习

### 练习 1：为什么完整项目第一步不是写代码？

参考答案：

因为完整项目需要先确定产品范围、角色、页面、业务流程、真实化标准和验收标准。否则代码可能越写越散，最后很难形成一个能演示、能部署、能写简历的完整项目。

### 练习 2：阶段 11 哪些组件必须真实化？

参考答案：

前端、Java Spring Boot、MySQL、Redis、Python FastAPI、真实 LLM、真实 embedding、真实 rerank、Qdrant、订单/工单/知识库/AI 对话主流程都应该真实化。

### 练习 3：为什么订单和工单不应该只存在向量数据库里？

参考答案：

向量数据库适合语义检索知识文档，不适合作为业务事实来源。订单和工单需要事务、权限、状态流转、审计和精确查询，应该由 Java 服务和 MySQL 管理。

## 自测题

### 自测 1：阶段 11 的一句话目标是什么？

答案：

把智能工单系统做成完整、真实、可运行、可演示、可写简历的 AI 应用项目。

### 自测 2：阶段 11 的主线和前面阶段有什么不同？

答案：

前面阶段以学习单个技术点为主，阶段 11 以项目集成为主。它要把前端、Java、Python AI、MySQL、Redis、向量数据库和真实模型整合成一个完整业务系统。

### 自测 3：当前第 1 节需要注册新平台或打开虚拟机吗？

答案：

不需要。本节只定义项目范围和真实化标准，不涉及外部服务运行。
