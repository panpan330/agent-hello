# 阶段 9 学习计划：RAG 进阶与检索质量优化

## 阶段定位

阶段 9 的主题是：

```text
RAG 进阶与检索质量优化。
```

这一阶段不是重新学习“什么是 RAG”，而是在已经完成基础 RAG、Qdrant、Milvus、LangGraph、Tool Calling、真实 Java 后端、MCP 的基础上，把 RAG 从“能跑通”推进到“能调优、能评测、能解释、能用于真实项目”。

之前基础 RAG 已经让系统具备：

- 文档加载。
- chunk 切分。
- embedding。
- 向量数据库入库。
- 向量检索。
- 引用来源。
- 权限过滤基础。
- Qdrant 主线实践。
- Milvus 对比理解。

阶段 9 要继续解决的问题是：

- 用户问法不标准时，系统怎么改写问题？
- 一个问题只检索一次够不够？
- 关键词检索和向量检索怎么结合？
- 检索分数到底能不能直接相信？
- rerank 为什么能提高答案质量？
- 答案引用是不是必须能对应原文？
- RAG 答错时，应该从哪里排查？
- 怎样设计可重复运行的 RAG 评测？
- 文档更新、删除、重建索引怎么处理？
- RAG 和 Agent 应该如何分工？

## 阶段目标

学完阶段 9 后，目标不是只会说“我做过 RAG”，而是能讲清楚：

```text
我能从查询改写、多路召回、混合检索、rerank、权限过滤、安全防护、引用校验、评测集、bad case 分析、参数调优、缓存降级和可观测性等角度，解释一个 RAG 系统为什么答得好或答得差，并能在项目里逐步改进它。
```

更具体地说，要达到这些能力：

- 能解释基础 RAG 的主要短板。
- 能解释 query rewrite、multi query、hybrid search、rerank 的作用边界。
- 能看懂向量检索分数、关键词检索分数和 rerank 分数的区别。
- 能设计 RAG 评测集，而不是只靠肉眼试几个问题。
- 能定位 RAG bad case 是数据问题、切分问题、召回问题、排序问题、prompt 问题、权限问题还是模型生成问题。
- 能做基础的 RAG 参数调优。
- 能把 RAG 的检索过程、引用、耗时、失败原因记录下来。
- 能把 RAG 与 LangGraph Agent 的职责边界讲清楚。

## 阶段 9 固定 24 节

| 节 | 主题 | 目标 |
| --- | --- | --- |
| 1 | RAG 进阶总览：为什么基础 RAG 还不够 | 建立阶段 9 的完整学习地图，理解基础 RAG 在真实项目中的典型短板 |
| 2 | Query Rewrite：用户问题改写 | 学会把口语化、含糊、不完整的问题改写成更适合检索的问题 |
| 3 | Multi Query：一个问题生成多个检索问题 | 理解为什么一个用户问题可能需要多种检索角度，提高召回覆盖面 |
| 4 | 查询意图识别：区分查政策、查订单、查流程、闲聊 | 学会在 RAG 前判断问题类型，避免所有问题都盲目查知识库 |
| 5 | Hybrid Search 进阶：关键词检索 + 向量检索融合 | 学习关键词检索和向量检索的互补关系，以及初步融合策略 |
| 6 | 检索分数理解：score、distance、相似度到底怎么看 | 理解不同检索系统分数方向、含义和不可直接横向比较的问题 |
| 7 | Rerank 进阶：召回后为什么还要重排序 | 理解粗召回和精排序的分工，知道 rerank 解决什么质量问题 |
| 8 | 真实 Rerank 模型接入 | 学会接入真实 rerank 模型，并保留 fake rerank 方便测试 |
| 9 | 引用来源校验：回答必须能对应原文 | 学会检查答案是否真的来自召回文档，减少编造和错引 |
| 10 | Context Compression：上下文压缩 | 理解为什么不能把所有 chunk 都塞给模型，学习压缩上下文的方法 |
| 11 | Metadata Filter：用户、租户、权限、业务域过滤 | 把检索范围限定在用户有权访问的文档和业务域内 |
| 12 | RAG Prompt Injection 防护 | 学习文档内容中恶意提示的风险，以及模型侧和系统侧防护边界 |
| 13 | RAG 评测集设计 | 学会设计问题、期望答案、期望来源、权限场景和拒答场景 |
| 14 | 检索指标：命中率、召回率、Top-K 命中 | 用指标判断检索是否把正确资料找出来，而不是只看最终回答 |
| 15 | 回答质量评测：正确性、引用一致性、拒答合理性 | 评估最终回答是否正确、是否引用一致、是否该拒答时拒答 |
| 16 | Bad Case 分析：怎么定位 RAG 答错的原因 | 建立 RAG 问题排查路径，区分数据、检索、排序、生成和权限问题 |
| 17 | 参数调优：chunk_size、overlap、top_k、score_threshold | 学会用可观察结果调整 RAG 参数，而不是凭感觉乱调 |
| 18 | RAG 缓存、超时、降级和性能优化 | 学习真实服务里 RAG 的响应时间、成本和可用性保护 |
| 19 | RAG 可观测性：记录 query、召回、rerank、引用、耗时 | 给 RAG 链路补齐排查所需日志和指标 |
| 20 | RAG 数据更新：增量入库、删除、重新索引 | 理解知识库文档变化后，向量库和索引如何保持一致 |
| 21 | RAG 多知识库路由 | 学习用户问题应该查哪个知识库，而不是所有资料混在一起检索 |
| 22 | RAG 与 Agent 的组合边界 | 讲清楚 RAG 负责查资料，Agent 负责流程决策和工具编排 |
| 23 | RAG 生产化验收清单：质量、安全、性能、成本、可观测性 | 整理一个真实 RAG 功能上线前应该检查什么 |
| 24 | 阶段 9 总复盘和面试表达强化 | 把阶段 9 的能力整理成项目表达、面试回答和后续学习路线 |

## 默认学习方式

阶段 9 继续沿用当前学习要求：

- 每节先讲基础知识铺垫，再进入本节主题系统讲解。
- 不默认已经懂新概念，尤其是 query rewrite、multi query、hybrid search、rerank、评测指标等内容。
- 笔记不能薄，要能支撑以后复习、开发和面试讲解。
- 练习题和自测题的答案放在对应题目下面，方便阅读。
- 代码只服务于学习目标，不为了写代码而写代码。
- 测试部分讲重点，不在笔记里大篇幅重复测试细节。
- 如果是纯知识节，不生成手动测试文档。
- 如果涉及虚拟机、Qdrant、Milvus、真实模型、环境变量、手动 curl 或脚本运行，再单独生成 manual-tasks 文档。
- 平时不做敏感信息扫描，只有上传 GitHub 时再做。
- README 不需要每节都大改，只在阶段计划、阶段总结或重要入口变化时更新。

## 环境说明

阶段 9 不会每节都需要打开 VMware Ubuntu。

默认情况：

```text
Windows 本地即可。
不需要真实大模型。
不需要 Qdrant / Milvus。
不需要启动 Java business service。
```

可能需要打开 VMware Ubuntu 的情况：

- 真实 Qdrant 检索。
- 真实 Milvus 对比。
- 向量库数据更新和删除。
- 真实多知识库检索。
- 需要 Docker 容器提供外部服务。

可能需要真实模型 API 的情况：

- Query Rewrite 真实模型版本。
- Multi Query 真实模型版本。
- 真实 rerank 模型接入。
- 回答质量评测中的 LLM-as-judge 扩展。

自动化测试默认仍然不真实调用大模型，使用 fake client、fake retriever、fake reranker 和固定样本保证测试稳定。

## 阶段边界

阶段 9 会重点学习 RAG 进阶能力，但不会把所有搜索系统都一次性展开。

本阶段暂不作为主线：

- Elasticsearch 深入实战。
- BM25 底层公式推导。
- 大规模分布式检索集群调优。
- 自研向量数据库。
- 模型微调。
- 复杂前端搜索控制台。
- Kubernetes 部署。
- 多模态 RAG。

这些内容不是不重要，而是当前阶段的目标是先把企业知识库 RAG 的工程主线补扎实。

## 阶段 9 第一节

第一节从这里开始：

```text
阶段 9 第 1 节：RAG 进阶总览：为什么基础 RAG 还不够
```

这一节主要解决：

- 基础 RAG 的典型流程是什么。
- 基础 RAG 为什么在真实项目中容易答错。
- 阶段 9 的 24 节分别补哪类问题。
- 判断 RAG 质量时，为什么不能只看模型最终回答。

这一节不需要打开虚拟机。
