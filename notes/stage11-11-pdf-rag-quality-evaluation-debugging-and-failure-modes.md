# M11 第 11 节：PDF/RAG 质量评估、排错与失败模式

## 本节定位

用户只会看到“答案错了”“没找到资料”或“引用不对”。但根因可能在文件接入、解析、清洗、分块、元数据、权限、召回、重排、上下文或模型生成任一层。本节学习把模糊体验拆成可复现、可定位、可回归的质量问题。

## 本节学习目标

1. 区分测试、评估、监控、告警和用户反馈。
2. 建立文档 RAG 的六层质量模型。
3. 设计包含例外、表格、版本、权限和拒答的评测集。
4. 通过失败现象定位责任层，而不是先换模型。
5. 将 bad case 变成长期质量资产。

## 一句话先讲透

**RAG 评估不是只判断答案像不像对的，而是逐层检查：资料读对了吗、证据找对了吗、证据支持结论吗、用户有权看吗、版本有效吗、证据不足时系统有边界吗。**

## 基础知识铺垫

### 1. 为什么 HTTP 200 不代表成功

接口成功只说明服务返回了响应。它仍可能引用旧版本、漏掉脚注、误解表格、越权召回、没有资料却自信回答。因此 AI 质量不能只由状态码或模型输出长度判断。

### 2. 测试、评估、监控和反馈

| 概念 | 主要问题 | 例子 |
| --- | --- | --- |
| 测试 | 确定性规则有没有被破坏 | 权限过滤、状态转移、参数校验 |
| 评估 | 检索和回答质量是否达标 | 正确证据是否在 top_k、引用是否支持 |
| 监控 | 线上运行是否异常 | 延迟、失败率、无资料率、成本 |
| 告警 | 是否需要及时介入 | 错误率或解析失败突然升高 |
| 用户反馈 | 真实场景哪里不满足 | 用户标记无帮助、反复追问 |

它们互补：测试防规则回退，评估测质量，监控看趋势，反馈发现未知长尾。

### 3. 什么是可复现问题

RAG 会受文档版本、分块、embedding、检索参数、权限、模型和 prompt 影响。要复现一个错误，至少保存问题、身份范围、目标时间、知识快照、配置版本、候选证据、回答和引用。否则问题明天可能“消失”，但并非真的被修好。

## 本节主题系统讲解

### 1. 六层质量模型

| 层 | 核心问题 | 常见失败 |
| --- | --- | --- |
| 文档接入 | 文件、分类、版本、权限正确吗 | 错知识库、缺页、错版本 |
| 解析清洗 | 文字、结构、表格、脚注保真吗 | 乱码、错序、例外丢失 |
| 分块元数据 | 证据完整、可追溯、可过滤吗 | 标题丢失、页码错、块重复 |
| 检索重排 | 找到正确且有权证据吗 | 漏召回、旧资料、相关块排名低 |
| 回答引用 | 忠实、完整、有边界吗 | 幻觉、过推断、伪引用 |
| 生命周期安全 | 更新、删除、权限持续正确吗 | 幽灵知识、越权、缓存串数据 |

这张表是排错地图：不要把所有问题都叫“模型效果差”。

### 2. 评测集应测什么

```text
直接事实：退款期限是多少？
条件题：什么情况下可以退款？
例外题：活动商品是否适用普通规则？
比较题：不同商品类型责任方有何区别？
表格题：某行某列的值、单位和口径是什么？
跨页题：续页条款是否保持完整？
版本题：某历史时点适用哪一版？
权限题：无权用户是否完全得不到敏感证据？
拒答题：资料不足时是否拒绝确定答案？
冲突题：资料冲突时是否按规则处理？
```

普通事实题容易正确，边界题才能暴露系统质量。

### 3. 一个评测样本应记录什么

```text
case_id、问题、用户/租户/角色、目标业务时间。
期望证据：文档、版本、页码、章节或块。
期望结论或允许答案范围。
是否应拒答、是否应转人工。
风险等级与失败分类。
知识快照、配置和数据集版本。
```

只存标准答案一句话不够，因为 RAG 还要验证引用、权限和版本。

### 4. 常见指标

```text
解析：空文本率、乱码率、页数覆盖、低 OCR 置信度比例。
分块：异常短长块、重复率、标题页码保留率。
检索：Recall@k、正确证据命中率、无资料率。
重排：正确证据进入前几名的比例。
回答：正确性、完整性、忠实性、拒答正确性。
引用：正确性、完整性、定位准确性、可访问性。
安全：越权召回率、失效文档命中率，应为零。
运行：延迟、成本、失败、重试趋势。
```

总分可能掩盖严重安全失败。一次越权或错版本不应被大量简单题的高分冲淡。

### 5. “没找到资料”的排错顺序

```text
原文真的有该信息吗？
相关页面被解析、清洗、分块了吗？
标题、语言、元数据正确吗？
是否被权限、状态、版本、有效期过滤？
正确块是否已召回但排名过低？
重排、阈值或上下文截断是否丢掉它？
模型是否拿到证据却未使用？
```

这能避免把“脚注根本没解析到”误当 embedding 问题。

### 6. “答错但有引用”的排错顺序

```text
引用是否真支持结论，还是仅主题相关？
模型是否漏掉同块中的例外？
是否混用了不同版本、地区或产品线资料？
表格表头、单位、行列关系是否损坏？
用户问题中的对象、时间、条件是否理解错？
结论是否超出证据强度？
```

有引用可能让错误更具迷惑性，因此引用质量要单独评估。

### 7. bad case 生命周期

```text
记录：问题、身份、响应、证据、引用、trace、版本。
分类：接入、解析、分块、元数据、检索、引用、权限或生成。
复现：固定快照确认问题稳定存在。
修复：修改真正责任层。
回归：加入受控评测集。
复盘：记录根因、影响和防再发措施。
```

bad case 不是“用户抱怨记录”，而是未来改模型、改分块、改权限时的安全网。

### 8. 离线评估与线上观察

离线评估可重复比较版本，线上观察能发现真实用户表达和长尾问题。线上可看无资料率、追问率、引用点击、转人工、延迟、成本和反馈趋势，但日志与反馈本身也需脱敏与权限控制。

### 9. 失败分类

```text
SOURCE_MISSING：资料不存在或未入库。
PARSE_LOSS：OCR、表格、脚注、顺序损失。
CHUNK_CONTEXT_LOSS：条件或例外被切断。
METADATA_ERROR：版本、页码、权限、状态错误。
RETRIEVAL_MISS：正确块未召回。
RERANK_ERROR：正确块排序过低。
CONTEXT_SELECTION_ERROR：证据被截断或混入冲突。
GENERATION_UNFAITHFUL：模型未忠实依据证据。
CITATION_ERROR：引用不支持或定位错误。
ACCESS_CONTROL_ERROR：越权或错误拒绝。
```

统一分类让团队能针对数据、检索、模型或安全层做正确修复。

## 常见误区

### 误区 1：答错先换更大模型

不对。大量错误在模型之前，尤其是解析、分块、版本和权限。

### 误区 2：只测常见问题

不对。例外、表格、跨页、版本、权限、拒答更能检验系统可靠性。

### 误区 3：bad case 修一次就结束

不对。必须加入回归集，防止后续改动复发。

## 本节练习

### 练习 1：为什么 200 不代表 RAG 成功？

答案：接口可成功返回，但内容仍可能错版本、越权、无证据、漏例外或引用错误。RAG 成功需要多层质量共同满足。

### 练习 2：用户说没找到资料，第一步不该做什么？

答案：不应立刻调 embedding 或换模型。先确认原文是否有信息、页面是否解析/分块/过滤正确。

### 练习 3：bad case 为什么要记录快照？

答案：资料、索引、模型和配置会变化；没有快照无法稳定复现根因，也无法证明修复有效。

## 自测题

### 自测 1：六层质量模型是什么？

答案：文档接入；解析清洗；分块元数据；检索重排；回答引用；生命周期安全。

### 自测 2：测试和评估的区别？

答案：测试验证确定性规则与契约；评估判断检索、证据和回答质量，二者都需要。

### 自测 3：本节最重要结论？

答案：RAG 错误必须分层定位并进入 bad case 回归闭环，不能只依靠感觉或单次手工提问优化。
